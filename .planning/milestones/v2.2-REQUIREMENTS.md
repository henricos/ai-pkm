## v2.2 Requirements

### Contrato de Ambiente

- [x] **ENV-01**: App falha no startup com mensagem clara se `APP_BASE_PATH` estiver ausente no ambiente. Validado na Phase 10.
- [x] **ENV-02**: App falha no startup com mensagem clara se `NEXTAUTH_URL` estiver ausente no ambiente. Validado na Phase 10.
- [x] **ENV-03**: App valida que o pathname de `NEXTAUTH_URL` coincide com `APP_BASE_PATH`; falha cedo com mensagem que mostra um exemplo correto se divergirem. Validado na Phase 10.

### Build e Configuração Next.js

- [x] **CFG-01**: `next.config.ts` usa `APP_BASE_PATH` como fonte do `basePath` do Next.js. Validado na Phase 10.
- [x] **CFG-02**: `release.yml` passa `--build-arg APP_BASE_PATH=/pkm` no step de `docker build`. Validado na Phase 10.
- [x] **CFG-03**: Existe helper `withBasePath(path)` central para construção de URLs absolutas e redirects server-side. Validado na Phase 10.

### Ajustes de Código

- [x] **APP-01**: Redirects em `src/app/(shell)/layout.tsx` e `src/app/(auth)/login/page.tsx` usam o prefixo configurado. Validado na Phase 11.
- [x] **APP-02**: `pages.signIn` do NextAuth e fallback de `callbackUrl` no `LoginForm` usam o prefixo configurado, com proteção contra open redirect. Validado na Phase 11.
- [x] **APP-03**: Rotas de preview e download em `viewer-page.tsx` e `viewer-header.tsx` usam o prefixo configurado. Validado na Phase 11.

### Testes

- [x] **TST-01**: Testes de env cobrem: falha quando `APP_BASE_PATH` está ausente; falha quando `NEXTAUTH_URL` está ausente; falha quando divergem; sucesso quando sincronizados. Validado na Phase 12.
- [x] **TST-02**: Testes de rotas cobrem: redirect não autenticado para `/pkm/login`; redirect pós-login para `/pkm`; `withBasePath()` produzindo prefixo correto para subpaths. Validado na Phase 12.

### Documentação Operacional

- [x] **DOC-01**: `docs/dev-setup.md` documenta como configurar `APP_BASE_PATH` no `.env`, com exemplos concretos e nota de que a raiz retorna 404. Validado na Phase 12.
- [x] **DOC-02**: `README.md` documenta o contrato dos 3 lugares de configuração — `.env`, workflow CI, `compose.yaml` — com explicação de que mudar o path exige nova release. Validado na Phase 12.

## Future Requirements

### Configurabilidade Avançada

- **FUT-01**: `APP_BASE_PATH` pode ser alterado em runtime sem rebuild da imagem (requer proxy com prefix stripping).
- **FUT-02**: App suporta múltiplos paths de base para ambientes distintos sem recompilar.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Reverse proxy local para strip do prefixo | Opção B (baked) foi escolhida conscientemente |
| `APP_BASE_PATH` como variável de runtime no container | `basePath` do Next.js é build-time; runtime configurability exige arquitetura diferente |
| Suporte a app na raiz com auth em subrota ou vice-versa | Tratado como configuração inválida; o sync check recusa |
