# Milestone v2.2: Base Path Configurado com Sincronia App/Auth

**Status:** ✅ SHIPPED 2026-04-18
**Phases:** 10-12
**Total Plans:** 8

## Overview

O milestone `v2.2` tornou a aplicação genuinamente consciente do prefixo de rota `/pkm`. O `basePath` do Next.js passou a ser configurado a partir de `APP_BASE_PATH`, baked no build via `--build-arg` no workflow do GitHub Actions. Um contrato de ambiente explícito garantiu que `APP_BASE_PATH` e `NEXTAUTH_URL` estivessem presentes e sincronizados no startup, com falha cedo e mensagem clara. Todos os hardcodes de `/` no código da aplicação foram substituídos pelo prefixo configurado. Testes cobrem o contrato de ambiente e o comportamento das rotas com prefixo. Documentação operacional cobre os 3 lugares de configuração sem depender de conhecimento implícito.

Um fix adicional foi entregue ao fechar o milestone: `library/page.tsx` e `inbox/page.tsx` foram criados para garantir que o layout de auth execute mesmo quando as rotas índice dessas seções são acessadas diretamente (sem segmento de item), prevenindo 404 sem redirect para login.

## Milestone Summary

**Key Decisions:**

- `basePath` do Next.js é build-time → mudar path exige nova release (aceito conscientemente)
- `APP_BASE_PATH` hardcoded no workflow (`/pkm`) — Opção B, sem variável GitHub Actions
- Cloudflare Tunnel preserva o path → app precisa ser genuinamente consciente do prefixo
- Em dev: `localhost:3000/pkm` é o acesso correto; raiz retorna 404
- `withBasePath()` usada apenas em fronteiras server-side (redirect, callbacks) — `next/link` prefixa automaticamente via `basePath` do framework
- `isValidCallback()` no `LoginForm` protege contra open redirect sem acoplamento com `process.env` no cliente

**Issues Resolved:**

- Redirects de auth ignorando `basePath` configurado (hardcode de `/login` e `/`)
- `pages.signIn` do NextAuth sem prefixo
- URLs de preview/download no viewer sem prefixo
- Rotas índice de `/library` e `/inbox` retornando 404 sem passar pelo layout de auth

**Issues Deferred:**

- `APP_BASE_PATH` configurável em runtime sem rebuild (requer proxy com strip de prefixo)
- Deploy remoto automatizado a partir do CI após publicação de imagem

**Technical Debt Incurred:**

- `next-auth` beta ainda na base; upgrades futuros precisam respeitar a cadeia de `pages.signIn` e `withBasePath()`
- Testes de Server Components via JSDOM limitam cobertura de comportamento HTTP real (redirect efetivo requer servidor rodando)
