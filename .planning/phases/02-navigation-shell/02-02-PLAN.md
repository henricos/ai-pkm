<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Authenticated request -> shell layout | O layout da shell só pode existir para sessão autenticada |
| Route params -> item workspace | Segmentos de URL definem qual item é carregado na área principal |
| Server snapshot -> client shell | O snapshot server-side é transferido para a UI interativa do rail |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | Elevation of Privilege | `src/app/(shell)/layout.tsx` | mitigate | Reaplicar `auth()` no layout server-side antes de carregar a shell, mantendo a dupla proteção já estabelecida na phase 1. |
| T-02-06 | Tampering | `library/[...path]/page.tsx` e `inbox/[item]/page.tsx` | mitigate | Decodificar params apenas via helpers canônicos de rota; não concatenar paths diretamente nas páginas. |
| T-02-07 | Information Disclosure | workspace do item | mitigate | Mostrar apenas título/tipo/estado nesta fase; nenhum conteúdo bruto, path absoluto ou sidecar deve vazar no workspace mínimo. |
| T-02-08 | Denial of Service | remount completo da shell | accept | O risco é baixo no contexto single-user; a mitigação principal é usar layout persistente do App Router para evitar remontagens desnecessárias. |
</threat_model>
