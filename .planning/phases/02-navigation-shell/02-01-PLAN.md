<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PKM read model -> navigation snapshot | Dados vindos do filesystem e dos índices entram na projeção consumida pela UI |
| Item identity -> URL href | IDs lógicos são transformados em segmentos navegáveis e compartilháveis |
| Inbox/library namespace -> component state | A UI confia que o snapshot separa corretamente escopos operacionais distintos |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `navigation-service.ts` ancestry e contagens | mitigate | Calcular ancestry e `count` exclusivamente no servidor a partir dos índices/read model já validados na phase 1; cobrir com testes determinísticos em `navigation-service.test.ts`. |
| T-02-02 | Information Disclosure | hrefs de itens | mitigate | Encodar segmentos e separar inbox/library em helpers dedicados; não expor paths absolutos nem sidecars no snapshot. |
| T-02-03 | Spoofing | distinção inbox vs library | mitigate | Tipar explicitamente o `scope` do item e gerar URL só via `route-helpers.ts`, sem concatenação livre nos componentes. |
| T-02-04 | Denial of Service | projeção estrutural grande | accept | O alvo continua single-user e local; custo é aceitável nesta fase, desde que a projeção seja server-side e reutilize índices existentes em vez de varrer o PKM inteiro sem necessidade. |
</threat_model>
