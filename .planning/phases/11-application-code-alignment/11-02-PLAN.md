<objective>
Corrigir `pages.signIn` do NextAuth e o fallback de `callbackUrl` no LoginForm, garantindo que ambos usem o prefixo configurado.

Purpose: `pages.signIn: "/login"` faz o NextAuth redirecionar para `/login` sem prefixo, quebrando o fluxo de autenticação. O fallback `callbackUrl ?? "/"` no LoginForm envia o usuário para a raiz sem prefixo após login. Como `login-form.tsx` é um Client Component, `process.env.APP_BASE_PATH` não está disponível no browser — a estratégia segura é calcular `withBasePath("/")` no Server Component (`login/page.tsx`) e passar como prop `fallbackUrl`.

Output:
- `src/lib/auth.ts` — `pages: { signIn: withBasePath("/login") }` (per D-02)
- `src/components/login-form.tsx` — aceita prop `fallbackUrl: string`; sanitização defensiva que rejeita callbacks sem basePath ou com `://` (per D-04, D-05)
- `src/app/(auth)/login/page.tsx` — calcula `fallbackUrl={withBasePath("/")}` e passa para `<LoginForm>` (server-side, sem problema de process.env)
</objective>

    ## Parte A — src/components/login-form.tsx

    1. Adicionar prop `fallbackUrl: string` à interface do componente:
       ```typescript
       export function LoginForm({ fallbackUrl }: { fallbackUrl: string }) {
       ```

    2. Substituir a linha:
       `const callbackUrl = searchParams.get("callbackUrl") ?? "/";`
       por:
       ```typescript
       const rawCallback = searchParams.get("callbackUrl");
       const callbackUrl = rawCallback && isValidCallback(rawCallback, fallbackUrl)
         ? rawCallback
         : fallbackUrl;
       ```

    3. Adicionar a função `isValidCallback` antes de `LoginForm` (não exportada):
       ```typescript
       function isValidCallback(url: string, baseFallback: string): boolean {
         // Rejeitar qualquer URL absoluta (contém "://") — previne open redirect (D-05, T-11-03)
         if (url.includes("://")) return false;
         // Aceitar apenas paths que começam com o basePath configurado
         // baseFallback é withBasePath("/") = "/pkm", então startsWith garante prefixo correto
         return url.startsWith(baseFallback);
       }
       ```

    Nota sobre process.env: `login-form.tsx` é "use client". O `fallbackUrl` chega como prop já calculada pelo Server Component pai — não há chamada a `process.env.APP_BASE_PATH` neste arquivo. Isso resolve o Pitfall 2 documentado na RESEARCH.md.
