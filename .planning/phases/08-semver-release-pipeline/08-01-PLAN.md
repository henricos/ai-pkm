## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI/build env -> Next build env | Versão e hash entram por variáveis externas e precisam ser previsíveis |
| Docker build args -> published UI | Metadados do commit atravessam a build e aparecem para o operador |
| Repository version source -> runtime display | `package.json` continua sendo a fonte de versão SemVer do app |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | next.config.ts build env | mitigate | Preferir `APP_VERSION` e `NEXT_PUBLIC_GIT_HASH` explícitos no build publicado e cobrir por teste estático |
| T-08-02 | Repudiation | login footer traceability | mitigate | Exibir versão + hash curto no produto e alinhar ambos ao mesmo contrato do build |
| T-08-03 | Denial of Service | release build metadata | mitigate | Manter fallback seguro para dev e validar o build com envs explícitas no verify automatizado |
</threat_model>
