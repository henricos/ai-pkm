## Spacing Scale

Declarado em múltiplos de 4. Tokens mapeados às classes Tailwind equivalentes.

| Token | Value | Classe Tailwind | Usage |
|-------|-------|-----------------|-------|
| xs | 4px | `p-1` / `gap-1` | Gaps de ícone, padding inline de badge |
| sm | 8px | `p-2` / `gap-2` | Espaçamento compacto entre elementos |
| md | 16px | `p-4` / `gap-4` | Espaçamento padrão entre elementos |
| lg | 24px | `p-6` / `gap-6` | Padding de seção, espaço entre campos do form |
| xl | 32px | `p-8` / `gap-8` | Gaps de layout |
| 2xl | 48px | `p-12` / `gap-12` | Quebras maiores de seção |
| 3xl | 64px | `p-16` / `gap-16` | Espaçamento de página |

Exceções: touch targets de botão de submit ≥ 44px de altura (acessibilidade).

## Notas de Implementação

- **Ponto focal:** o card de login centralizado na viewport é o único elemento de destaque — sem nav, header ou sidebar nesta fase. O botão "Entrar na conta" é o CTA principal e recebe a cor de accent.
- **Tela de login:** layout centrado verticalmente na viewport, card único contendo o formulário. Minimalismo como padrão enquanto `DESIGN.md` não existir.
- **Responsividade:** card de login com largura máxima de 400px, responsivo em mobile (w-full com padding lateral md).
- **Acessibilidade:** campos com `id` e `htmlFor` correspondentes; botão de submit com `type="submit"`; mensagem de erro associada ao formulário via `role="alert"`.
- **Sem conteúdo visual adicional:** Fase 1 não inclui nav, sidebar, header ou qualquer shell de navegação — esses são Fase 2.
- **Âncora de estilo:** quando `DESIGN.md` for commitado na raiz, o agente deve ler o arquivo e atualizar `globals.css` com os tokens concretos antes de implementar quaisquer componentes.
